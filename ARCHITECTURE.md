# Архитектура

1. `dataset/` содержит исходные записи, снимок сайта и изображения; `data/` — проверенную разметку. Production-галерея `dataset/vino-svoe/gallery-reviewed-candidates.jsonl` объединяет проверенные ссылки на 1 936 SKU. `ml/src/wine_cv/catalog.py` по-прежнему формирует историческую strict gallery для сравнения.
2. `ml/src/wine_cv/siglip.py` нормализует входное фото, применяет закреплённый SigLIP 2 с обученным адаптером и ранжирует эталоны по cosine similarity. Для каждого эталона используются полная бутылка и кроп этикетки, запрос остаётся полным кадром. Индекс и кэши сохраняются в игнорируемом `work/`.
3. `ml/src/wine_cv/api.py` отдаёт результат поиска. Nuxt-прокси в `frontend/server/api/v1/` возвращает плоский `{"slug":"..."}` оценочному скрипту и расширенный JSON интерфейсу.
4. `frontend/app/` показывает найденную карточку, каталог и дополнительную функцию — подбор вина и аналогов. `eval/participant_test.sh` последовательно отправляет фотографии и сохраняет ответы и время.

Границы, форматы кэша и методика оценки подробно описаны в [ML-архитектуре](ml/docs/ARCHITECTURE.md). Сходство изображения не является вероятностью или F1 для отдельного запроса; для отказа от ответа нужны отдельно откалиброванные пороги.

Для одного Nuxt-сервиса без GPU есть отдельно включаемый dHash fallback на старом компактном индексе 928 эталонов. Это не production SigLIP-режим и не заменяет новую галерею.
