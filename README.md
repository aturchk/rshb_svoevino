# Сканер вин «Своё Вино»

Мобильный сайт на Nuxt и локальный сервис поиска вина по фотографии бутылки на SigLIP 2. Исходное задание — [`task/10. РСХБ.Цифра.pdf`](task/10.%20РСХБ.Цифра.pdf). Устройство проекта описано в [ARCHITECTURE.md](ARCHITECTURE.md).

## Локальный запуск

Нужны Python 3.10+, Node.js 22.23.2 (см. `frontend/.nvmrc`), npm и интернет для первого скачивания модели. Из корня репозитория:

```bash
nvm use 22.23.2          # если используете nvm
make local
```

Первый запуск создаёт `.venv`, устанавливает зависимости, готовит каталог, обучает адаптер, если его ещё нет, строит поисковый индекс и поднимает Nuxt и ML API. На CPU подготовка может занять существенно больше времени. После сообщения `Full local application is ready` откройте <http://127.0.0.1:3000/scan>. Остановка — `Ctrl+C`. Логи — в `work/local/logs/`.

Для быстрой проверки только интерфейса:

```bash
make install
make demo
```

Демо-режим помечен в интерфейсе и возвращает заранее заданные сценарии без распознавания фотографии. Для камеры на телефоне нужен HTTPS-адрес в той же сети: браузеры не выдают доступ к камере по обычному HTTP с локальным IP. Загрузка файла работает и без камеры.

## Интерфейс сканера

Откройте `/scan`, разрешите камеру и поместите **бутылку целиком в кадр**. Видоискатель показывает весь поток камеры; кнопка затвора отправляет весь кадр, без обрезки по рамке. Можно также выбрать снимок из галереи. Перед отправкой браузер ориентирует изображение при декодировании, уменьшает длинную сторону до 1280 пикселей и сохраняет JPEG с качеством 0,86. Это уменьшает объём передачи; влияние сжатия на точность реальных снимков отдельно не измерялось.

Во время поиска видны этапы обработки и кнопка отмены. Результат открывается поверх снимка: найденное вино с карточкой, менее уверенный вариант с альтернативами либо сообщение, что вино не найдено. Из результата можно повторить съёмку или перейти к поиску по названию. Доступность камеры зависит от браузера и разрешения пользователя; интерфейс предлагает загрузку фото, если камера недоступна.

## Как работает распознавание

И каталог, и снимок проходят один и тот же ML-процессор: учёт EXIF-ориентации, RGB, ограничение большого изображения по стороне, затем стандартные изменение размера и нормализация цветов SigLIP 2. Эмбеддинги приводятся к единичной длине; поиск сравнивает их косинусное сходство. При обучении адаптера используются увеличенные виды каталожных изображений: случайное приближение и сдвиг, поворот до 9°, вариации яркости, контраста и насыщенности, иногда размытие, блик и небольшое перекрытие. Эти приёмы обучают устойчивости, но при обычном сканировании дополнительных случайных преобразований нет. Автоматическое выделение бутылки или этикетки, OCR, коррекция перспективы и удаление бликов в текущем поиске не реализованы. В поиск идёт **весь отправленный снимок**.

## Точность и ограничения

| Показатель | Измерение | Что означает |
| --- | ---: | --- |
| Top‑1 и micro F1@1 | 94,07% | Правильный первый кандидат на 928 синтетически преобразованных запросах с известным ответом |
| Recall@5 | 99,89% | Правильное вино среди первых пяти на том же наборе |
| Задержка ML p50 / p95 | 53,99 / 84,89 мс | Только поиск после загрузки модели на NVIDIA RTX PRO 4500 Blackwell, CUDA bfloat16; не время ответа сайта на телефоне |
| Покрытие strict gallery | 928 из 2 103 позиций | Остальные позиции каталог показывает, но поиск по фото для них не гарантирован |

Источник чисел — [зафиксированный отчёт proxy-прогона](docs/presentation/ml-status/evidence/proxy-siglip-summary.json) для SigLIP 2 **с обученным адаптером**. Они не относятся к запуску базовой модели без адаптера и **не являются точностью на реальных полевых фото**. В [ручной разметке](docs/presentation/ml-status/evidence/field-validation.json) есть 100 фотографий: 64 подтверждённые позиции каталога, 35 вне каталога и 1 неопределённая; лишь 23 из 64 подтверждённых позиций входят в strict gallery. Это общий размеченный пул, а не независимый тестовый набор. Точность на закрытом наборе и качество отказа от неверного ответа пока неизвестны; пороги уверенности не откалиброваны. Результат сканера следует проверять по названию, году и типу вина. Подробности — в [ml/README.md](ml/README.md).

## Индекс и воспроизводимость

Каталожные данные и исходные изображения хранятся в репозитории; `make local` строит индекс в `work/siglip-cache/`. Сам бинарный индекс не зафиксирован в Git, потому что его валидность зависит от версии модели и процессора, адаптера, порядка и хешей изображений, precision и версий PyTorch/Transformers. При изменении этих входов индекс перестраивается; неверный кэш отклоняется при загрузке. Это также позволяет не выдавать локальный индекс базовой модели за индекс модели с обученным адаптером. Созданные галереи, веса и кэши остаются в игнорируемом `work/`.

## Проверки и тестовый прогон

После подготовки полного стека запустите из корня репозитория:

```bash
make test
```

Команда проверяет данные, Python и Nuxt тесты, линтер, типы, сборку и HTTP-сценарий. Для пробного прогона оценочного скрипта оставьте `make local` работающим в первом терминале и выполните во втором:

```bash
eval/participant_test.sh \
  --images-dir eval/queries \
  --manifest eval/queries.tsv \
  --endpoint http://127.0.0.1:3000/api/v1/eval/predict \
  --output work/predictions.jsonl
```

Скрипту нужны `bash`, `curl`, `jq`, `awk` и `shasum` или `sha256sum`. Три фото в `eval/queries/` проверяют формат ответа и время; правильных ответов для них нет. Для повторного прогона выберите новое имя выходного файла или удалите предыдущий.

Когда организатор выдаст закрытый пакет, поместите его в `eval/test/` согласно [инструкции](eval/test/README.md), остановите обычный сервер и запустите `make october-test`. Протокол и ограничения результата описаны в [eval/README.md](eval/README.md).

## Конфигурация

`make local` использует порты 3000 (Nuxt) и 8080 (ML). `ML_DEVICE=auto` выбирает CUDA, Apple MPS или CPU. `NUXT_ML_BASE_URL` указывает адрес ML-сервиса; `NUXT_PUBLIC_DEMO_SCAN=true` включает только демонстрацию интерфейса. Для запуска через Docker есть [.env.example](.env.example) и `compose.yaml`.
