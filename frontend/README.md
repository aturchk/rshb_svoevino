# Сканер вин «Своё Вино» — фронтенд

Веб-модуль каталога российских вин для платформы [«Своё Вино»](https://vino-svoe.ru).
MVP без ML: распознавание этикеток — заглушка со сформированным швом под будущий сервис.

## Запуск

Нужен Node **22.23+** (в проекте есть `.nvmrc`).

```bash
nvm use
npm ci
npm run build:images   # один раз: ресайз фотографий из ../dataset (~11 с)
npm run dev            # http://localhost:5173
```

Готовые `public/data` и `public/img` закоммичены, поэтому после `npm ci` приложение
запускается сразу — `build:images` нужен только при обновлении датасета.

| Команда                                          | Что делает                                             |
| ------------------------------------------------ | ------------------------------------------------------ |
| `npm run dev`                                    | дев-сервер                                             |
| `npm run build`                                  | `prebuild` (сборка датасета) → `tsc -b` → `vite build` |
| `npm run build:data`                             | CSV → JSON, ~0.2 с                                     |
| `npm run build:images`                           | ресайз фото с кэшем; `-- --force` пересобирает всё     |
| `npm run lint` / `format` / `typecheck` / `test` | проверки                                               |

Флаг `VITE_ENABLE_MOCK_SCAN_HISTORY=true` включает демо-записи в истории сканирования
(по умолчанию раздел пуст — выдавать выдуманные сканы за настоящие нельзя).

## Пересборка датасета

Источник — `../dataset/strapi_output0709.csv` (путь переопределяется `DATASET_DIR`).
Скрипт падает с внятным сообщением, если дамп изменился: проверяются состав колонок,
4147 строк и 2103 уникальных slug.

```
public/data/dict.json            справочники (индексы уходят в URL)
public/data/wines.index.json     колоночный индекс, 245 КБ raw / 43 КБ gzip
public/data/facets.json          состав значений и диапазон крепости
public/data/wines/{slug}.json    карточка, ~626 байт gzip
public/img/{thumb,detail}/…      бутылки 96px и 320px
```

## Архитектура

Feature-Sliced, зависимости идут строго вниз:

```
app → pages → widgets → features → entities → shared
```

Направление проверяется ESLint-правилом `import/no-restricted-paths` с зонами: оно
резолвит путь и ловит в том числе `../../features/x`, тогда как `no-restricted-imports`
смотрит только на строку импорта. Скриптам сборки разрешён единственный слой — `shared`.

Внутри среза модули импортируют друг друга относительными путями и никогда через
собственный `index.ts` — иначе получаются циклы и ломается tree-shaking.

Контракт сгенерированных файлов живёт в `shared/config/dataset-schema.ts`: его должен
видеть и скрипт сборки, которому слой `entities` недоступен. Доменные типы приложения —
`entities/wine/model/types.ts`.

## Решения по производительности

**CSV не парсится в браузере.** Конвертация в `prebuild`, RFC4180-парсером: в файле
6326 физических строк на 4147 записей — переводы строки живут внутри закавыченных
описаний, наивный `split('\n')` разваливается.

**Колоночный индекс** (structure of arrays). Выигрыш не в весе — gzip и так жмёт
повторяющиеся ключи — а в том, что при загрузке не аллоцируется 2103 объекта, а
фильтрация идёт по `Uint8Array`/`Uint16Array`/`Float32Array`.

**Файл на вино, а не шарды.** Детальная запись — 705 байт против 61 КБ у шарда из 88
позиций: шард тянул бы в 24 раза больше нужного. Карточка денормализована, поэтому
прямой заход на `/wine/:slug` — ровно один запрос, без индекса и справочников.

**Инвертированные индексы** `Map<значение, Uint32Array>` строятся за один проход при
загрузке (~0.4 мс) и в JSON не хранятся: типизированных массивов там нет. Запрос —
гибрид: пересечение постинг-листов по категориальным фасетам, затем линейный проход по
кандидатам для подстроки и диапазона крепости (диапазон через Map не выражается).

**Счётчики фасет — динамические**, по схеме «без учёта собственного условия». Статические
счётчики врут, как только выбран любой фильтр; значения с нулём становятся `disabled`,
а не скрываются, иначе панель прыгает под курсором.

**Web Worker не включён** — по правилу «если фильтрация превысит ~10 мс». Замер:
**0.344 мс** на 2103 позициях с пересчётом всех счётчиков. Шов готов: `runQuery` уже
изолирован от React и DOM. Путь эскалации честнее описать так: воркер не ускорит
0.3 мс, при росте каталога на два порядка нужен n-gram индекс для подстроки.

**Три времени поиска разведены явно:** значение поля — локальный стейт (0 мс);
применение фильтра — 0 мс; запись в URL — debounce 250 мс и всегда `replace`, иначе
набор слова «шардоне» кладёт в историю семь записей и «назад» перестаёт работать.

**Виртуализация** — `@tanstack/react-virtual` по оконному скроллу, чтобы sticky-хедер
работал штатно. Высота строки фиксирована (88/112 px), поэтому `measureElement` не
нужен — нет прохода измерений и дёрганья скроллбара. Ключ элемента — slug, а не индекс
массива: иначе при смене фильтра React переиспользует DOM не тех строк. Позиция скролла
восстанавливается при возврате с карточки, но только если фильтры не изменились.

**Анимация сканера** — только `transform` и `opacity`. Панель это фиксированный оверлей,
место под неё резервирует распорка в потоке. В кадре 0 распорка схлопывается (документ
мгновенно принимает финальную высоту) и тут же контенту выдаётся компенсирующий
`transform`; со следующего кадра включается transition. Поэтому нет ни пустой полосы
внизу, ни рывка в конце. Состояние — автомат с обработкой `transitionend`,
`transitioncancel` и страховочным таймером: повторный тап переключает направление.

**Изображения** — `loading="lazy"`, `decoding="async"`, реальные размеры каждого файла
пишутся в индекс и задают точный `aspect-ratio`: нулевой CLS без допущений.
Генерация кэшируется по `sha1(путь + mtime + размер + параметры)` — повторный прогон
меньше секунды вместо 107; `sharp` импортируется динамически и только когда есть работа.

**Разделение кода.** Главный чанк 102.8 КБ gzip; каталог вместе с движком фильтрации и
загрузчиком датасета — отдельные 13.5 КБ, карточка 1.7 КБ. Датасет грузится при открытии
каталога; на титульном экране он лишь префетчится по `requestIdleCallback` и по наведению
на кнопку, то есть после отрисовки первого экрана и низшим приоритетом.

## Что взято из данных, а чего в них нет

Девять колонок дампа заполнены на 100% (сорт — 99.9%), но заполненность ≠ пригодность.
Три поля выведены из названия и артикула на этапе сборки:

| Поле         | Покрытие  | Как получено                                           |
| ------------ | --------- | ------------------------------------------------------ |
| Сахар        | 81.6%     | регексп по названию и slug                             |
| **Крепость** | **75.2%** | хвост slug и имени фото: `…-krasnoe-suhoe-135` → 13.5% |
| Игристое     | 13.1%     | признак в названии                                     |

Крепость подтверждена двумя независимыми источниками: они совпали в 1534 случаях и
разошлись в нуле. Это единственное числовое поле каталога, и на нём построен range-слайдер.

**Год** есть у 116 позиций из 2103 (5.5%) — ниже порога 30%, в UI не выводится.
**Цвет** заполнен на 100%, но это 826 свободнотекстовых значений; как фильтр непригоден,
поэтому идёт в карточку рядом с нормализованным семейством.
**Фотографии** резолвятся для 992 позиций (47.2%) — остальных файлов физически нет в
выданном пакете. Для них рисуется силуэт бутылки в цвете категории: подставлять чужое
фото вместо настоящего нельзя.
**Цены, рейтинга, отзывов, гастропар, крепости как поля, объёма** в дампе нет вообще.
Поэтому блок «оценки» в карточке не рендерится — точка расширения описана в конце
`pages/WineDetailsPage/WineDetailsPage.tsx`.

## Шов под ML

`entities/scan/api/recognizeWine.ts` — типизированная сигнатура и заглушка:

```ts
recognizeWine(image: Blob, signal?: AbortSignal): Promise<RecognizeResult>

interface RecognizeResult {
  status: 'matched' | 'low_confidence' | 'not_found'
  top1: RecognizeCandidate | null
  top5: RecognizeCandidate[]
  latencyMs: number
}
```

Форма ответа выбрана под две вещи сразу: скрипт оценки кейсодержателя ждёт плоский
top-1 со `slug`, а продуктовый сценарий «вина нет в каталоге» должен отличаться от
«нашли, но не уверены». Подмена заглушки на HTTP-вызов не затрагивает слой фич.

## Тесты

`npm test` — 34 теста на чистых функциях: деривация крепости, сахара, цвета, сорта;
пересечение и объединение постинг-листов; фильтрация и счётчики фасет. Тесты идут по
настоящему сгенерированному датасету, а не по синтетике, поэтому ловят и регрессии
скрипта сборки. Окружение `node`, без jsdom и testing-library.
